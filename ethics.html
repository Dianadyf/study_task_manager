Ethical Data Use in This Application

Which features support the ethical use of data?

The application collects only the minimum information needed for it to work: a task title, a course code and name, a due date, a short description and a priority level. Nothing is collected that could identify the user beyond what the user chooses to type into the task themselves. Ethical data use is also supported by transparency - the user can see every piece of data the application holds, because all tasks are displayed in the task table at all times, and the user can edit or permanently delete any of that data at any moment.

In addition, the confirmation dialog shown before deleting a task is an ethical design choice: it prevents data from being destroyed accidentally, which respects the effort the user invested in creating it.

Data Privacy in This Application

Which features support data privacy?

Three design decisions protect the privacy of the user's data:

  1. Access is restricted by a login system. The Task Manager page cannot be used without a username and password, so another person using the same computer cannot view or change the student's tasks.
  2. Data stays on the user's own device. Tasks are stored in the browser's localStorage. The application has no server and sends nothing over the internet, which means no third party can access the user's study data.
  3. Minimal data collection. The app deliberately does not ask for a real name, email address, phone number or any student ID, so there is no personal information to leak, lose or misuse.

Examples of Ethical and Privacy-Aware Design

The following concrete examples show how moral and privacy-conscious design was applied while building this web application:

  • Input validation. Every field is validated before saving - required fields cannot be left empty and impossible dates (such as 30 February) are rejected. This is ethical because it prevents the system from storing corrupt or meaningless data that could mislead the user later.
  • Login-controlled access. A simple username/password check gates the task page. Password input is masked on screen so it is not visible to people nearby.
  • Deleting with confirmation. The confirm() dialog shows exactly which task will be deleted before the action is performed, giving the user full control over their own data.
  • Output escaping. All user-entered text is HTML-escaped before it is rendered back into the task table, which protects users from script injection through their own task descriptions.

Reflection

Building this application taught me that ethical responsibility and privacy are not optional extras in web development - they are design decisions that must be made from the very beginning. Even in a small, personal project like a study task manager, choices such as how much data to collect, where the data lives, who can see it and how easily it can be removed all affect real users. When applications handle user-generated data, developers have a duty to collect less, protect what is collected, and always give users control over their own information.
